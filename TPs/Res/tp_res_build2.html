Séquence Réseau — TP noté · Filius

Deux réseaux locaux, un routeur, et internet

Stagiaire chez Tech'Usine : l'entreprise fait agrandir ses locaux. Vous devez mettre en service deux réseaux locaux — l'atelier (plan d'adressage fourni) et l'administratif (plan à concevoir et justifier) — les relier par un routeur, puis modéliser la sortie vers internet. Ce TP est noté : la grille est en bas de page.

1ʳᵉ Bac Pro CIEL TP noté /20 Simulateur Filius Binôme (une maquette commune, questions individuelles)
01

Ce que vous allez faire

Objectifs
  • Chantier 1 (guidé) : construire le LAN de l'atelier d'après un dossier technique fourni — switch, 3 postes, serveur, DHCP et DNS.
  • Chantier 2 (autonome, noté) : construire le LAN administratif — cette fois, c'est vous qui concevez le plan d'adressage et le justifiez.
  • Chantier 3 : relier les deux LAN avec un routeur et configurer les passerelles.
  • Chantier 4 : ajouter un troisième réseau « internet » avec un serveur web distant, et prouver que les deux LAN peuvent le consulter.
Comment on travaille

Une maquette Filius par binôme. Les questions et la justification du plan d'adressage se rédigent individuellement : chacun rend son propre compte rendu.

Rendu

Sur Pronote, chaque élève dépose avant la fin de la séance : un seul fichier PDF (compte rendu + questions + plan d'adressage justifié) et le fichier Filius techusine_final.fls. La maquette finale doit être sauvegardée et fonctionnelle.

02

Chantier 1 — Le LAN de l'atelier (plan donné)

Guidé
Situation professionnelle

Tech'Usine vous confie la mise en service du réseau de l'atelier. Le dossier technique est prêt : appliquez-le exactement, puis prouvez que tout fonctionne.

Le dossier technique (à appliquer tel quel)

                   ┌──────────────────┐
                   │    SW-ATELIER    │   switch
                   └──┬─────┬────┬───┘
                      │     │    │
            ┌─────────┘     │    └─────────┐
            │               │              │
     ┌──────┴──────┐ ┌──────┴───────┐ ┌────┴────────┐
     │     SRV     │ │ PC-ATELIER-1 │ │ PC-ATELIER-2│
     │192.168.10.10│ │192.168.10.11 │ │192.168.10.12│
     │ IP fixe     │ │ IP fixe      │ │ IP fixe     │
     │DHCP+DNS+Web │ │              │ │             │
     └─────────────┘ └──────────────┘ └─────────────┘
     Réseau : 192.168.10.0 · Masque : 255.255.255.0
     DNS : intranet.techusine.fr → 192.168.10.10
Élément Adresse IP Masque Remarque
Réseau de l'atelier 192.168.10.0 255.255.255.0 plage privée
SRV 192.168.10.10 255.255.255.0 IP fixe — DHCP, DNS et web
PC-ATELIER-1 192.168.10.11 255.255.255.0 IP fixe
PC-ATELIER-2 192.168.10.12 255.255.255.0 IP fixe
Plage DHCP (réservée aux futurs postes) .100 à .150 255.255.255.0 activée sur SRV
Nom interne du serveur intranet.techusine.fr — enregistrement DNS

À vous de jouer

  1. 1
    Construire la maquette
    • Mode Design : placez le switch (renommez-le SW-ATELIER), 2 Notebook et 1 PC (le serveur), et renommez chaque machine comme le dossier.
    • Câblez en étoile, puis passez en mode Simulation : les voyants passent au vert.
  2. 2
    Configurer les adresses fixes

    Retour en mode Design : renseignez les IP du dossier (SRV, PC-ATELIER-1, PC-ATELIER-2) avec le masque 255.255.255.0.

  3. 3
    Mettre en service DHCP, DNS et web sur SRV
    • DHCP Server : plage 192.168.10.100 à 192.168.10.150, masque 255.255.255.0, DNS 192.168.10.10, puis Activer.
    • DNS Server : enregistrement intranet.techusine.fr → 192.168.10.10, puis Start.
    • Web Server : lancez-le, puis Start.
  4. 4
    Prouver que ça communique

    Depuis le Command Line de PC-ATELIER-1, notez le résultat de chaque test :

    N° Commande Résultat attendu Mon résultat ✔ / ✘
    1 ping 192.168.10.12 PC-ATELIER-2 répond
    2 ping 255.255.255.255 toutes les machines répondent
    3 host intranet.techusine.fr le DNS renvoie 192.168.10.10
    4 navigateur : http://intranet.techusine.fr la page s'affiche par le nom

Chantier 2 — Le LAN administratif (plan à concevoir)

Autonome · Noté
Situation professionnelle

Tech'Usine ouvre un bureau administratif : 1 serveur (DHCP + DNS + web), 2 postes fixes et 1 poste en DHCP — avec une croissance prévue. Cette fois, personne ne vous donne le dossier : rédigez le vôtre, appliquez-le dans Filius, et justifiez chaque choix.

  1. 1
    Rédiger votre dossier technique

    Complétez ce tableau dans votre compte rendu — c'est votre plan d'adressage :

    Élément Votre choix Justification (une phrase)
    Adresse du réseau
    Masque
    SRV-ADMIN
    PC-ADMIN-1
    PC-ADMIN-2
    PC-ADMIN-3 (en DHCP)
    Plage DHCP
    Nom interne du serveur
    • Rappels pour bien choisir (cliquer pour déplier)
      • Les 3 plages privées : 10.x.x.x, 172.16.x.x à 172.31.x.x, 192.168.x.x.
      • L'atelier utilise déjà 192.168.10.0/24 : votre réseau administratif devra être différent (on les reliera au chantier 3).
      • .0 (réseau) et la dernière adresse (diffusion) ne sont jamais attribuées.
      • IP fixes basses pour les serveurs ; plage DHCP haute, sans chevaucher les fixes.
    Question 1 — notée

    Justifiez vos trois choix principaux : la plage privée choisie, la place du serveur dans votre plan, et le début de votre plage DHCP. Utilisez le vocabulaire du cours (privé, IP fixe, plage, conflit d'adresses).

  2. 2
    Construire et mettre en service
    • Dans le même fichier Filius (éloignez la maquette de l'atelier sur l'écran) : nouveau switch SW-ADMIN, 3 Notebook et 1 PC SRV-ADMIN, câblage en étoile.
    • Appliquez votre plan : IP fixes, DHCP avec votre plage, DNS avec votre nom, web sur SRV-ADMIN.
  3. 3
    Prouver que ça communique

    Depuis PC-ADMIN-1 : ping de PC-ADMIN-2, ping de SRV-ADMIN, host de votre nom interne, et site web consulté par son nom. Notez les résultats.

    Validation chantier 2

    Le réseau administratif fonctionne conformément à votre dossier, et votre tableau d'adressage est justifié.

Chantier 3 — Relier les deux LAN par un routeur

Passerelles
Situation

L'entreprise veut que l'atelier et l'administratif communiquent : les postes de l'administratif doivent consulter le site interne de l'atelier. On installe un routeur entre les deux réseaux. 

   RÉSEAU ATELIER (votre réseau 1)         RÉSEAU ADMIN (votre réseau 2)
        SW-ATELIER                             SW-ADMIN
            │       ┌────────────┐                │
            └───────┤  ROUTEUR   ├────────────────┘
                    │ if A : ……  │  ← une adresse du RÉSEAU 1
                    │ if B : ……  │  ← une adresse du RÉSEAU 2
                    └────────────┘
  1. 1
    Installer et configurer le routeur
    • Placez un Routeur entre les deux switchs et câblez-le vers chacun.
    • Onglet General → Manage Connections : ajoutez une 2ᵉ carte réseau. Donnez à la 1ʳᵉ interface une adresse du réseau atelier, à la 2ᵉ une adresse du réseau administratif.
    • Choisissez pour le routeur des adresses libres de chaque plan (en dehors des IP fixes et de la plage DHCP).
  2. 2
    Configurer les passerelles de tous les postes
    • Sur chaque poste et chaque serveur : renseignez la passerelle = l'adresse du routeur dans son propre réseau.
    • Aide : la règle de la passerelle (cliquer pour déplier)
      • La passerelle est la « porte de sortie » du réseau : elle doit être une adresse du réseau auquel appartient le poste.
      • SRV (atelier) → interface « atelier » du routeur. SRV-ADMIN (administratif) → interface « administratif » du routeur.
    Question 2 — notée

    SRV (atelier) veut joindre SRV-ADMIN (administratif). Expliquez le trajet du message en nommant les trois adresses IP importantes (source, passerelle, destination) et le rôle du switch puis du routeur.

  3. 3
    Tester entre les deux LAN

    Depuis PC-ATELIER-1 :

    N° Commande Résultat attendu Mon résultat ✔ / ✘
    1 ping <passerelle atelier> le routeur répond
    2 ping <passerelle admin> la 2ᵉ interface répond
    3 ping <IP de SRV-ADMIN> SRV-ADMIN répond
    4 navigateur : site web de SRV-ADMIN la page administrative s'affiche
    Question 3 — notée

    Pourquoi le ping direct PC-ATELIER-1 → SRV-ADMIN ne fonctionnait-il pas avant le routeur ? Que limite le routeur entre les deux réseaux (indice : le test 2 du ping de diffusion ?)

    Piège classique

    Pour tester le site web de SRV-ADMIN par son nom depuis l'atelier, le plus simple est de l'ouvrir par son adresse IP. Enregistrer le nom admin dans le DNS de l'atelier est possible, mais pas demandé ici.

05

Chantier 4 — Modéliser la sortie vers internet

Réseau public
Situation

Le chef d'entreprise veut visualiser comment ses postes sortent sur internet. Dans Filius, on modélise internet par un troisième réseau : des adresses publiques et un serveur web distant. On ajoute une 3ᵉ interface au routeur : une interface par réseau, c'est la règle.

   RÉSEAU ATELIER              RÉSEAU ADMIN              INTERNET (modélisé)
   192.168.10.0                (votre plan)              198.51.100.0/24 (public)
       │ SW-ATELIER   ┌────────────┐   SW-ADMIN │                 │
       └──────────────┤  ROUTEUR   ├────────────┘       ┌──────────┴──────┐
                      │            ├────────────────────┤   WEB-DISTANT   │
                      │ interfaces │                    │  198.51.100.10  │
                      │  if A : …  (réseau 1)           │  site externe   │
                      │  if B : …  (réseau 2)           └─────────────────┘
                      │  if C : 198.51.100.1 (public)
                      └────────────┘
  1. 1
    Créer le réseau « internet »
    • Placez un PC nommé WEB-DISTANT (serveur), configurez-le : IP 198.51.100.10, masque 255.255.255.0, passerelle 198.51.100.1, et installez un Web Server (Start).
  2. 2
    Ajouter l'interface internet au routeur
    • Double-clic sur le routeur → onglet General → Manage Connections : ajoutez une 3ᵉ carte réseau, câblez-la vers WEB-DISTANT, et donnez-lui l'adresse 198.51.100.1 (masque 255.255.255.0).
    • Aide : pourquoi 198.51.100.0 ? (cliquer pour déplier)
      • C'est une plage publique réservée à la documentation : elle ne peut pas être confondue avec vos réseaux privés, et elle n'est jamais routée sur le vrai internet.
      • Un réseau d'internet doit être public : utiliser 192.168.1.0 serait un faux internet.
  3. 3
    Orienter les passerelles
    • Sur tous les équipements des deux LAN : la passerelle devient 198.51.100.1 ? Non : la passerelle reste l'interface du routeur dans le réseau du poste — elle est juste désormais capable de joindre aussi le réseau internet.
    • C'est la route par défaut : « tout ce que je ne connais pas, je l'envoie à ma passerelle » ; le routeur, lui, connaît ses trois réseaux et transmet.
  4. 4
    Prouver la sortie internet

    Depuis PC-ATELIER-1 et PC-ADMIN-1 :

    N° Commande Résultat attendu Mon résultat ✔ / ✘
    1 ping 198.51.100.10 WEB-DISTANT répond
    2 navigateur : http://198.51.100.10 le site externe s'affiche
    Question 4 — notée

    a) Dans la vraie vie, un poste de l'atelier a une adresse privée : comment peut-il être compris par un serveur d'internet qui, lui, n'utilise que des adresses publiques ? Donnez le nom du mécanisme.
    b) Pourquoi les postes gardent-ils la même passerelle (l'interface du routeur dans leur réseau) alors qu'ils vont maintenant sur internet ?

    Validation chantier 4

    Le site 198.51.100.10 s'ouvre depuis un poste de chaque LAN. Votre modèle est complet : deux LAN privés, un routeur, un réseau public.

    Ce que Filius simplifie

    Filius n'implémente pas le NAT : chaque réseau est simplement routé. Dans la réalité, le routeur d'accès traduit les adresses privées en une adresse publique — c'est le mécanisme de la question 4a.
