Séquence Web — Séance 1 · Mission n°1

Le voyage d'une requête web

Vous tapez une adresse dans un navigateur et, en moins d'une seconde, la page s'affiche.

Pourtant, derrière ce simple clic, des dizaines d'équipements ont travaillé ensemble. Vous êtes le technicien chargé d'enquêter : identifier chaque acteur du trajet et prouver ce qui circule.

Suivez les étapes, cochez au fur et à mesure, remplissez votre compte rendu.

1ʳᵉ Bac Pro CIEL Durée : 2 h Poste Windows
01

Ce que vous allez apprendre

Objectifs
  • Décoder une URL et distinguer ses parties (schéma, domaine, chemin).
  • Décrire le modèle client-serveur et le rôle de chaque acteur (client, serveur, DNS, FAI).
  • Observer une requête et une réponse HTTP dans le navigateur.
  • Interpréter les codes de statut HTTP (200, 404, 403…) et les ports associés (80 / 443).

Compétences visées

Bloc 3 · U32 — Analyser une structure matérielle et logicielle Décoder l'acheminement d'une page web
Bloc 2 · U31 — Exploiter un réseau informatique Découvrir le dialogue client-serveur
Bloc 3 · U32 — Coder Se préparer à publier
02

Ce qu'il faut savoir avant de commencer

Prérequis
Notion L'essentiel
Adresse IP Identifiant logique d'un équipement sur un réseau (ex. 172.217.19.35). C'est elle qui permet de joindre un serveur.
Serveur DNS L'annuaire qui traduit un nom de domaine (www.education.gouv.fr) en adresse IP. Vu au TP « Réseaux — bases ».
Ping Outil de test de connectivité : il prouve qu'un équipement est joignable .
Port « Porte » logique d'un service sur une machine. Un serveur web « écoute » sur le port 80 (HTTP) ou 443 (HTTPS).
Navigateur web Logiciel client : il formule des requêtes HTTP et affiche les réponses du serveur.
Matériel nécessaire
  • Un poste en binôme, connecté à Internet.
  • Un navigateur (Firefox ou Chrome/Edge) et son éditeur de texte.
  • Une invite de commandes (Windows : Windows + R → cmd).
03

Étape 1 — Décoder une URL

15 min

Créer un compte rendu de TP. Conservez le, il vous permeettra de suivre vos apprentissages et il vous sera parfois demandé en fin de séance.

  1. 1
    Anatomie d'une URL

    Recopiez dans votre compte rendu l'URL complète de cette page de TP, puis découpez-la : 

    https://tansignoret.github.io/1ERE_CIEL/TPs/tp_web_bases.html
└─┬─┘   └──────────┬──────────┘└────┬────┘└─────────┬──────────┘
schéma           domaine          dossier        fichier
    Question 1

    1. Pour chaque partie de l'URL, expliquez qui la choisit : l'utilisateur, le propriétaire du site, ou personne (imposée) ?

    2. Que signifie le s de https ? Quel port est utilisé, comparé au HTTP ?

  2. 2
    Qui se cache derrière le nom ?

    Le navigateur, lui, ne comprend que les adresses IP. Dans l'invite de commandes, saisissez :

    nslookup tansignoret.github.io
ping tansignoret.github.io
    Question 2

    1. Quelle information le DNS a-t-il fournie ? Recopiez l'adresse IP obtenue.

    2. Le ping réussit-il ? Pourquoi est-ce un « ping » sur un nom qui fonctionne alors que la commande n'accepte que des adresses ?

04

Étape 2 — Surprendre la requête HTTP

25 min
  1. 1
    Ouvrir les outils de développement
    • Dans le navigateur : F12 (ou menu → « Plus d'outils » → « Outils de développement »).
    • Ouvrez l'onglet Réseau (Network), puis rechargez la page (F5).
    • La liste se remplit : ce sont tous les échanges HTTP nécessaires à l'affichage de la page.
    Question 3

    Combien de requêtes sont nécessaires pour afficher cette page du TP ? Pourquoi plusieurs, alors que vous n'avez tapé qu'une seule adresse ?

  2. 2
    Lire la requête et la réponse

    Cliquez sur la première requête de la liste (le document HTML), puis documentez dans votre compte rendu :

    Information Où la trouver Valeur relevée
    Méthode (GET…) colonne « Méthode »
    Code de statut colonne « Statut »
    Adresse du serveur (IP distante) panneau « Timer » ou « Remote address »
    Port distant à côté de l'IP distante
    Type de contenu (Content-Type) onglet « En-têtes » → En-têtes de réponse
    Question 4

    1. Que signifie le code 200 ? À votre avis, que signifient 404 et 403 ? Testez en tapant une adresse inexistante du site (ex. tp_web_bases2.html) et relevez le code obtenu.

    2. Comparez l'IP distante relevée ici avec celle obtenue à l'étape 1 avec nslookup : que remarquez-vous ?

  3. 3
    Requête ≠ réponse

    Dans le panneau de la requête, observez les deux blocs d'en-têtes :

    • « En-têtes de requête » (envoyés par le client)
      • Host : le site demandé
      • User-Agent : le navigateur utilisé
    • « En-têtes de réponse » (envoyés par le serveur)
      • Server : le logiciel serveur
      • Content-Type : le type de document renvoyé
    Question 5

    Rangez dans un tableau à deux colonnes « envoyé par le client » / « envoyé par le serveur » : le nom du navigateur, le code de statut, le site demandé, le type de contenu. Justifiez chaque rangement.

05

Étape 3 — Identifier les acteurs du voyage

20 min
  1. 1
    Relever la route

    Saisissez la commande :

    tracert tansignoret.github.io

    Chaque ligne est un routeur traversé par votre requête.

    Question 6

    1. Combien d'étapes environ séparent votre poste du serveur ? Recopiez les 3 premières.

    2. Le premier routeur de la liste est probablement la passerelle de l'atelier : pourquoi votre requête passe-t-elle d'abord par elle ?

  2. 2
    Ping ne suffit pas !

    Un serveur peut être joignable (le ping répond) mais ne pas servir de pages (le service web est arrêté). Testez :

    ping tansignoret.github.io
ping 127.0.0.1
    Question 7

    1. Que prouve le succès du ping vers le site ? Que ne prouve-t-il pas ?

    2. À quoi reconnaît-on, dans le navigateur, qu'un serveur est joignable mais que le service web ne répond pas ? (indice : codes de statut…)

06

Étape 4 — Le schéma du voyage

20 min
  1. 1
    Dessiner l'acheminement

    Sur votre compte rendu, dessinez le trajet complet d'une requête tapée sur https://tansignoret.github.io :

    • Poste (client) → switch → passerelle → routeurs du FAI → serveur DNS → serveur web.
    • Reportez les adresses IP relevées pendant le TP (passerelle, serveur DNS, serveur web).
    • Indiquez sur le schéma où le nom de domaine est traduit en IP et où le document HTML est fabriqué.
    Question 8

    Sur votre schéma, fléchez en vert la requête HTTP (client → serveur) et en rouge la réponse (serveur → client). Quel acteur du schéma n'apparaît qu'une seule fois dans le dialogue, au tout début ? Justifiez.

  2. 2
    Contrôle croisé

    Échangez votre schéma avec le binôme voisin : chaque binôme doit retrouver sur le schéma de l'autre les 5 acteurs et les 2 flèches du dialogue.

    À retenir

    Une page web n'est pas « téléchargée depuis le ciel » : c'est un dialogue HTTP entre un client (le navigateur) et un serveur, guidé par le DNS. La semaine prochaine, vous installerez ce serveur… sur votre propre poste.

09

Lexique

Vocabulaire
Mot Définition
Client Programme qui émet une requête et attend une réponse (ex. le navigateur web).
Serveur Machine ou programme qui écoute en permanence sur un port et répond aux clients.
HTTP / HTTPS Protocole d'échange du web (requête/réponse) ; HTTPS est la version chiffrée (port 443 contre 80).
URL Adresse d'une ressource : schéma (https) + domaine + chemin + fichier.
Nom de domaine Nom lisible désignant un serveur (ex. github.io), traduit en IP par le DNS.
Code de statut Nombre renvoyé par le serveur : 200 = succès, 404 = introuvable, 403 = interdit, 301 = déplacé.
En-têtes (headers) Informations jointes à la requête ou à la réponse (navigateur, serveur, type de contenu…).
HTML Langage de description des pages web ; le document échangé dans ce TP. On le produira en séance 4.
FAI Fournisseur d'accès à Internet : ses routeurs acheminent la requête jusqu'au serveur.
