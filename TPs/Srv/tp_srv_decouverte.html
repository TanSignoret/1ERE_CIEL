Séquence Web — Séance 1 · Mission n°1

Le voyage d'une requête web

Vous tapez une adresse dans un navigateur et, en moins d'une seconde, la page s'affiche.

Derrière ce simple clic, des dizaines d'équipements ont travaillé ensemble. Vous êtes le technicien chargé d'enquêter : identifier chaque acteur du trajet, prouver ce qui circule, et expliquer pourquoi.

01

Ce que vous allez apprendre

Objectifs
  • Décoder une URL et distinguer ses parties (schéma, domaine, chemin).
  • Décrire le modèle client-serveur et le rôle de chaque acteur (client, serveur, DNS, FAI).
  • Observer une requête et une réponse HTTP dans le navigateur.
  • Interpréter les codes de statut HTTP (200, 404, 403…) et les ports associés (80 / 443).
  • Maîtriser les outils de diagnostic en ligne de commande : ping, nslookup, tracert.
  • Chercher par vous-même : retrouver une information technique à partir d'une observation.

02

Ce qu'il faut savoir avant de commencer

Prérequis
Notion L'essentiel
Adresse IP Identifiant logique d'un équipement sur un réseau (ex. 172.217.19.35). C'est elle qui permet de joindre un serveur.
Serveur DNS L'annuaire qui traduit un nom de domaine (www.education.gouv.fr) en adresse IP. Vu au TP « Réseaux — bases ».
Ping Outil de test de connectivité : il prouve qu'un équipement est joignable (mais pas qu'un serveur web fonctionne !).
Port « Porte » logique d'un service sur une machine. Un serveur web « écoute » sur le port 80 (HTTP) ou 443 (HTTPS).
Navigateur web Logiciel client : il formule des requêtes HTTP et affiche les réponses du serveur.
Matériel nécessaire
  • Un navigateur.
  • Un éditeur de texte.
  • Une invite de commandes (Windows : Windows + R → cmd).
03

Exercice 1

Guidé

Créer un compte rendu de TP. Il faudra le déposer sur Pronote au format PDF à la fin de la séance. Il participera à l'évaluation.

Objectif de la phase : savoir ouvrir les outils de développement et lire un échange HTTP. Suivez la procédure à la lettre.

  1. 1
    Ouvrir les outils de développement
    • Aller sur le site de l'ent du lycée.
    • Dans le navigateur : F12 (ou menu → « Plus d'outils » → « Outils de développement »).
    • Ouvrez l'onglet Réseau (Network).
    • Rechargez la page et le cache (Ctrl + F5) : la liste se remplit d'échanges HTTP.
    • Je n'y arrive pas, à quoi doit ressembler l'écran ?
      • Un panneau s'ouvre à droite ou en bas de la fenêtre.
      • Un tableau avec plusieurs colonnes : Nom, Statut, Type, Taille, Temps.
      • Si le tableau est vide : rechargez la page avec le panneau ouvert.
  2. 2
    Compter les échanges

    Relevez dans votre compte rendu le nombre de requêtes nécessaires à l'affichage de la page.

    Question 1

    Pourquoi plusieurs requêtes, alors que vous n'avez tapé qu'une seule adresse ?

  3. 3
    Lire la requête principale

    Cliquez sur la première requête de la liste (le document HTML), puis relevez :

    Information Où la trouver Valeur relevée
    Méthode (GET…) colonne « Méthode »
    Code de statut colonne « Statut »
    Adresse du serveur (IP distante) panneau « Remote address »
    Port distant à côté de l'IP distante
    Type de contenu (Content-Type) onglet « En-têtes » → En-têtes de réponse
  4. 4
    Décoder l'URL de la page

    Recopiez l'URL complète de cette page, puis découpez-la :

    https://tansignoret.github.io/1ERE_CIEL/TPs/tp_web_bases.html
└─┬─┘   └──────────┬──────────┘└────┬────┘└─────────┬──────────┘
schéma           domaine          dossier        fichier
    Question 2

    Que signifie le s de https ? Quel port est utilisé, comparé au HTTP ? (indice : vos relevés du tableau ci-dessus)

  5. 5
    Tester la connectivité — découverte de ping

    Vous venez de relever l'adresse IP du serveur. Vérifions qu'elle est joignable avec l'outil ping : il envoie un petit message à la machine et attend sa réponse.

    Ouvrez l'invite de commandes (Windows + R → cmd) et saisissez, en remplaçant ADRESSE par l'IP relevée dans le tableau ci-dessus :

    ping ADRESSE        (ex. ping 185.199.108.153)
    • Mon IP contient des « : » (ex. 2606:50c0:8000::153) — c'est une IPv6 !
      • Utilisez alors la commande : ping -6 ADRESSE
      • -6 force le ping en IPv6 ; sans option, Windows essaie en IPv4 et peut échouer alors que le serveur répond très bien en IPv6.
    • Comment lire le résultat ?
      • Chaque ligne « Réponse de … » = un message aller-retour réussi, avec le temps en millisecondes.
      • « Délai d'attente dépassé » = pas de réponse : machine injoignable ou qui bloque le ping.
      • Les dernières lignes font le bilan (envoyés, reçus, perdus).
    Question 3

    1. Quel temps de réponse obtenez-vous ? Testez aussi ping 127.0.0.1 et comparez.

    2. Un ping réussi vers le serveur prouve-t-il que la page web s'affichera ? Justifiez.

Point de contrôle n°1

Présentez à l'enseignant vos réponses aux questions 1 à 3.

  2. 2
    Outil — nslookup : « quel est ton numéro ? »

    Vous avez relevé les IP après le chargement des pages. Mais comment le navigateur les connaît-il avant ? C'est le travail du serveur DNS, interrogé avec l'outil nslookup. Dans l'invite de commandes, saisissez : 

    nslookup www.education.gouv.fr
    • Comment lire le résultat ?
      • La 1ʳᵉ partie indique quel serveur DNS a répondu (souvent celui du lycée ou du FAI).
      • La 2ᵉ partie donne la réponse : Name (le nom demandé) et Address (l'IP trouvée).
      • Plusieurs adresses peuvent être renvoyées : le site est hébergé sur plusieurs serveurs.
    Question 5

    Quelle adresse IP le DNS a-t-il fournie pour www.education.gouv.fr ? Comparez avec celle relevée dans le navigateur : que remarquez-vous ?

  1. 1
    Outil — tracert : « par où es-tu passé ? »

    Le tracert liste tous les routeurs traversés par la requête, dans l'ordre. Saisissez :

    tracert tansignoret.github.io
    • Comment lire le résultat ?
      • Chaque ligne = un saut (un routeur), avec 3 mesures de temps.
      • Les * * * signifient qu'un routeur ne répond pas au tracert : ce n'est pas une panne, beaucoup refusent délibérément.
      • La commande peut prendre du temps : laissez-la se terminer.
    Question 7

    Combien de sauts séparent votre poste du serveur ?

08

Lexique

Vocabulaire
Mot Définition
Client Programme qui émet une requête et attend une réponse (ex. le navigateur web).
Serveur Machine ou programme qui écoute en permanence sur un port et répond aux clients.
HTTP / HTTPS Protocole d'échange du web (requête/réponse) ; HTTPS est la version chiffrée (port 443 contre 80).
URL Adresse d'une ressource : schéma (https) + domaine + chemin + fichier.
Nom de domaine Nom lisible désignant un serveur (ex. github.io), traduit en IP par le DNS.
Code de statut Nombre renvoyé par le serveur : 200 = succès, 404 = introuvable, 403 = interdit, 301 = déplacé.
En-têtes (headers) Informations jointes à la requête ou à la réponse (navigateur, serveur, type de contenu…).
HTML Langage de description des pages web ; le document échangé dans ce TP. On le produira en séance 3.
FAI Fournisseur d'accès à Internet : ses routeurs acheminent la requête jusqu'au serveur.
Ping / ICMP Outil de test de connectivité : il envoie une requête et attend une réponse.
Tracert Outil qui liste les routeurs traversés par la requête, dans l'ordre (les « sauts »).
