Le voyage d'une requête Web

Comprendre les échanges entre un navigateur et un serveur Web, identifier les acteurs du réseau et maîtriser les premiers outils de diagnostic.

Introduction

Comprendre

Que se passe-t-il lorsqu'on consulte un site Web ?

Lorsqu'un utilisateur saisit une adresse dans son navigateur, plusieurs opérations sont réalisées avant que la page ne s'affiche.

Le navigateur joue le rôle de client : il demande des ressources à un serveur Web.

Navigateur → DNS → Réseau → Serveur Web

Le serveur retourne ensuite les ressources demandées au navigateur, qui les interprète et les affiche.

À retenir Internet est un réseau de réseaux. Le Web est un service qui utilise Internet pour échanger des documents et des ressources entre clients et serveurs.

Exercice 1 — Observer une communication Web

Correction guidée

Question 1 — Pourquoi plusieurs requêtes ?

Réponse Une page Web ne correspond généralement pas à un seul fichier. Elle est constituée de plusieurs ressources que le navigateur doit récupérer.
Ressource Rôle
HTML Structure et contenu de la page.
CSS Mise en forme et présentation.
JavaScript Interactions et fonctionnalités dynamiques.
Images Illustrations, logos et photographies.
Polices Affichage des caractères.
Généralisation — Une page est un assemblage de ressources Le navigateur effectue plusieurs requêtes HTTP pour récupérer les différents éléments nécessaires à l'affichage. Une seule page peut ainsi entraîner des dizaines de requêtes. Ces ressources peuvent provenir de plusieurs serveurs.

Lire une requête HTTP

Dans l'onglet Réseau (Network) des outils de développement, on peut observer les informations suivantes :

Information Exemple Explication
Méthode GET Le navigateur demande une ressource.
Statut 200 La requête a été traitée avec succès.
Port distant 443 Port HTTPS classique.
Content-Type text/html Le serveur transmet un document HTML.
Attention Les adresses IP, les temps de réponse et certains paramètres peuvent varier selon le serveur, le réseau et le moment de la consultation.

Généralisation — Le modèle client-serveur

Le modèle client-serveur repose sur un échange :

  1. Le client formule une demande.
  2. Le serveur reçoit cette demande.
  3. Le serveur traite la demande.
  4. Le serveur renvoie une réponse.
  5. Le client interprète la réponse.
Client Programme qui demande un service. Exemple : navigateur Web.
Serveur Programme qui fournit un service et répond aux demandes des clients.

Question 2 — Que signifie le S de HTTPS ?

Réponse HTTPS signifie HyperText Transfer Protocol Secure. Le S signifie Secure : sécurisé.

HTTPS utilise TLS (Transport Layer Security) pour sécuriser les échanges entre le navigateur et le serveur.

TLS apporte principalement :

  • La confidentialité grâce au chiffrement.
  • L'intégrité des données transmises.
  • L'authentification du serveur grâce à son certificat.
Protocole Port par défaut Utilisation
HTTP 80 Communication Web sans TLS.
HTTPS 443 Communication Web sécurisée par TLS.
Généralisation — Qu'est-ce qu'un port ? Une adresse IP permet d'identifier une interface réseau. Un port permet d'identifier un service de communication sur cette machine.

On peut comparer l'adresse IP à l'adresse d'un immeuble et le port au numéro d'un appartement.

Quelques ports importants

Port Protocole Fonction
20 / 21 FTP Transfert de fichiers
22 SSH Administration distante sécurisée
25 SMTP Envoi de courriels
53 DNS Résolution de noms
80 HTTP Web
110 POP3 Réception de courriels
143 IMAP Consultation de courriels
443 HTTPS Web sécurisé
3389 RDP Bureau à distance Windows

Ces ports sont conventionnels. Un service peut être configuré pour utiliser un autre port.

Question 3 — Tester la connectivité avec ping

La commande ping permet d'envoyer des messages ICMP Echo Request à une machine et d'attendre des réponses ICMP Echo Reply. 

ping ADRESSE_IP

Le résultat indique notamment :

  • Le nombre de paquets envoyés.
  • Le nombre de réponses reçues.
  • Le nombre de paquets perdus.
  • Le temps de réponse en millisecondes.
Cas fréquent — Adresse IPv6 Si l'adresse relevée dans le navigateur contient des « : » (par exemple 2606:50c0:8000::153), c'est une adresse IPv6. Sous Windows, il faut alors forcer le ping en IPv6 : 
ping -6 ADRESSE_IPV6
Sans l'option -6, Windows essaie en IPv4 et le ping peut échouer alors que le serveur répond très bien en IPv6.

Comparer avec 127.0.0.1

ping 127.0.0.1
Réponse L'adresse 127.0.0.1 correspond à la boucle locale (localhost). Elle désigne toujours la machine sur laquelle la commande est exécutée.

La comparaison permet de constater que :

  • Le ping vers 127.0.0.1 teste localement la pile réseau.
  • Le ping vers un serveur distant nécessite de passer par le réseau.

Un ping réussi garantit-il l'affichage du site ?

Réponse Non. Un ping réussi prouve seulement que la machine répond aux requêtes ICMP. Il ne garantit pas que son serveur Web fonctionne.

Inversement, certains serveurs bloquent volontairement les requêtes ICMP. Un ping peut donc échouer alors que le site Web fonctionne.

Généralisation — Trois notions à distinguer
  • Connectivité réseau : les équipements peuvent-ils communiquer ?
  • Disponibilité d'un service : le service est-il accessible ?
  • Fonctionnement applicatif : l'application fonctionne-t-elle correctement ?
Un équipement peut être joignable sans que tous ses services soient disponibles.

Question 5 — Utiliser nslookup

Le DNS (Domain Name System) permet d'associer un nom de domaine à une adresse IP. 

nslookup www.education.gouv.fr

Exemple de résultat

Serveur :  dns.lycee.fr
Address :  192.168.1.1

Réponse ne faisant pas autorité :
Nom :    www.education.gouv.fr
Address : 129.88.205.26

Interprétation :

  • 192.168.1.1 correspond au serveur DNS interrogé (ici, celui du lycée ou du FAI).
  • www.education.gouv.fr est le nom recherché.
  • L'adresse retournée permet de contacter le serveur correspondant.
  • Plusieurs adresses peuvent être renvoyées : le site est hébergé sur plusieurs serveurs.

Pourquoi l'adresse peut-elle être différente de celle du navigateur ?

Plusieurs explications sont possibles :

  • Le site utilise plusieurs serveurs.
  • Un système de répartition de charge distribue les connexions.
  • Un CDN dirige les utilisateurs vers un serveur proche.
  • Les réponses DNS peuvent varier selon la localisation.
  • Le navigateur peut utiliser une information déjà présente dans son cache.
Réponse — Qui fournit l'information ? C'est le serveur DNS qui a fourni l'adresse IP. Il intervient avant l'envoi de la requête HTTP : le navigateur a besoin de l'adresse IP pour savoir à quelle machine envoyer la requête.
Généralisation — Le fonctionnement du DNS
  1. L'utilisateur saisit un nom de domaine.
  2. L'ordinateur vérifie si la correspondance est déjà connue (cache).
  3. Si nécessaire, il interroge un serveur DNS.
  4. Le DNS retourne une ou plusieurs adresses IP.
  5. Le navigateur peut contacter le serveur correspondant.
Le DNS permet donc d'utiliser des noms faciles à mémoriser plutôt que des adresses IP.
Attention — Ne pas confondre DNS permet de retrouver une adresse IP à partir d'un nom. HTTP permet d'échanger des ressources Web.

Question 6 — Provoquer une erreur HTTP

On demande au serveur une page qui n'existe pas, par exemple en modifiant le nom du fichier dans l'URL du TP : 

https://tansignoret.github.io/1ERE_CIEL/TPs/Srv/tp_srv_decouverte2.html
Réponse — Code HTTP 404 404 — Not Found. Cela signifie que le serveur a été contacté mais que la ressource demandée n'a pas été trouvée.

Le serveur est-il en panne ?

Non. Si le serveur renvoie une réponse 404, cela signifie généralement qu'il a reçu et traité la requête.

Le service fonctionne suffisamment pour répondre, mais il ne trouve pas la ressource demandée.

Généralisation — Les codes de statut HTTP
Famille Signification Exemple
1xx Information Traitement en cours
2xx Succès 200 OK
3xx Redirection 301 Moved Permanently
4xx Erreur liée à la requête 404 Not Found
5xx Erreur côté serveur 500 Internal Server Error

Quelques codes à connaître

  • 200 OK : requête traitée correctement.
  • 301 : ressource déplacée définitivement.
  • 302 : redirection temporaire.
  • 403 : accès refusé.
  • 404 : ressource introuvable.
  • 500 : erreur interne du serveur.
  • 503 : service temporairement indisponible.

Correction autonome

Question 7 — Utiliser tracert

La commande tracert permet d'observer les différents sauts réseau entre l'ordinateur et une destination. Chaque saut correspond à un routeur traversé par les sondes. 

tracert tansignoret.github.io

Exemple de résultat

  1     1 ms     1 ms     1 ms  192.168.1.1
  2     5 ms     4 ms     5 ms  10.0.0.1
  3    12 ms    11 ms    13 ms  xxx.xxx.xxx.xxx
  4     *        *        *     Délai d'attente dépassé.
  5    20 ms    19 ms    21 ms  185.199.108.153

Les adresses et les temps sont uniquement des exemples. Le nombre de sauts dépend du réseau utilisé.

Réponse — Combien de sauts ? Il n'y a pas de valeur unique : le nombre de sauts dépend du réseau (lycée, domicile, opérateur) et du moment. On observe généralement entre 5 et 20 sauts pour un site hébergé à l'étranger comme tansignoret.github.io. L'important est de savoir lire le résultat : le premier saut est la passerelle, les suivants sont les routeurs du FAI puis ceux de l'hébergeur.

Que signifient les étoiles ?

Attention Les étoiles indiquent que les sondes n'ont pas reçu de réponse dans le délai prévu. Cela ne signifie pas nécessairement que le routeur est en panne : certains équipements filtrent ou limitent les réponses aux sondes.

Généralisation — Le rôle des routeurs

Les données circulent généralement à travers plusieurs réseaux et équipements intermédiaires.

Les routeurs déterminent vers quelle destination transmettre les paquets à l'aide de leurs tables de routage.

Notion importante — TTL TTL signifie Time To Live.

Les sondes utilisées par tracert possèdent une durée de vie. À chaque passage par un routeur, le TTL diminue.

Lorsqu'il atteint zéro, le routeur abandonne le paquet et peut renvoyer un message ICMP.

Cela permet à tracert de découvrir progressivement les équipements traversés.
À ne pas confondre tracert observe le chemin suivi par ses propres sondes. Ce chemin n'est pas nécessairement strictement identique à celui des communications HTTPS du navigateur.

Question 8 — Quel est le premier équipement traversé ?

Réponse Dans une configuration réseau classique, le premier équipement est la passerelle par défaut, généralement le routeur du réseau local (au lycée : la passerelle du réseau pédagogique).

Pourquoi passe-t-on par cet équipement ?

L'ordinateur possède une configuration réseau :

  • Adresse IP.
  • Masque de sous-réseau.
  • Passerelle par défaut.
  • Serveur DNS.

Lorsque l'ordinateur souhaite communiquer avec une adresse située en dehors de son réseau local, il transmet généralement les paquets à sa passerelle par défaut.

Exemple de configuration

Équipement Adresse IP
Ordinateur 192.168.1.20
Imprimante 192.168.1.30
Passerelle 192.168.1.1
Serveur distant 185.199.108.153

Dans cet exemple, l'ordinateur et l'imprimante appartiennent au même réseau IP avec un masque /24.

Ils peuvent donc communiquer directement au niveau IP, sans passer par la passerelle par défaut.

Pour joindre le serveur distant, l'ordinateur utilise sa passerelle.

Généralisation — Réseau local et réseau distant
  • Destination dans le réseau local : communication directe au niveau IP.
  • Destination dans un autre réseau : transmission vers la passerelle par défaut.

Question 9 — Comprendre HTTPS

1. Que garantit HTTPS par rapport à HTTP ?

HTTPS utilise TLS pour sécuriser les échanges. Il apporte trois garanties principales.

Confidentialité Les données sont chiffrées pour empêcher leur lecture directe par une personne qui intercepterait les communications.
Intégrité Les mécanismes de protection permettent de détecter les modifications non autorisées des données.
Authentification Le certificat numérique permet au navigateur de vérifier l'identité du serveur.
Attention HTTPS ne garantit pas qu'un site est honnête ou sans danger. Un site frauduleux peut également utiliser HTTPS.

2. Que fait le navigateur avant d'afficher la page ?

Le navigateur ne se contente pas d'afficher le fichier HTML. Il réalise plusieurs opérations.

  1. Analyse du HTML : le navigateur construit une représentation de la structure de la page appelée DOM.
  2. Récupération des ressources : il identifie les fichiers CSS, images, JavaScript et polices nécessaires.
  3. Application des styles : il analyse les feuilles CSS pour déterminer l'apparence des éléments.
  4. Exécution du JavaScript : les scripts peuvent modifier le contenu et ajouter des fonctionnalités.
  5. Affichage : le navigateur calcule la position et les dimensions des éléments, puis dessine la page.

Généralisation — Les technologies du Web

Technologie Fonction
HTML Structure de la page.
CSS Présentation et mise en forme.
JavaScript Interactions et fonctionnalités.
HTTP / HTTPS Communication client-serveur.
DNS Résolution des noms de domaine.

Cours de synthèse

À retenir

1. Les grandes étapes d'une consultation Web

Lorsqu'un utilisateur saisit https://www.education.gouv.fr, voici les principales opérations réalisées.

Étape Action Acteur / protocole
1 L'utilisateur saisit une URL. Navigateur
2 Le navigateur identifie le nom de domaine. URL
3 Le nom est traduit en adresse IP. DNS
4 L'ordinateur détermine si la destination est locale ou distante. IP
5 Les paquets sont transmis vers la passerelle si nécessaire. Routeur
6 Les paquets circulent sur Internet. Routeurs
7 Une communication sécurisée est établie. TCP / TLS
8 Le navigateur envoie une requête. HTTP
9 Le serveur retourne une réponse. HTTP
10 Le navigateur interprète les ressources et affiche la page. HTML / CSS / JS
Complément technique Cette description concerne le fonctionnement classique d'HTTPS sur TCP. HTTP/3 utilise QUIC, qui repose sur UDP et intègre les mécanismes de sécurisation TLS. Le navigateur peut également réutiliser des informations en cache et charger plusieurs ressources en parallèle.

2. Les différentes couches de communication

Une communication Web fait intervenir plusieurs protocoles qui ont chacun un rôle précis.

Technologie Rôle
Ethernet / Wi-Fi Communication sur le réseau local.
IP Acheminement des paquets entre réseaux.
TCP ou QUIC Transport des données.
TLS Sécurisation des communications.
HTTP Échange des ressources Web.
À retenir Pour une communication HTTPS classique :
  • IP permet d'acheminer les paquets.
  • TCP assure le transport.
  • TLS sécurise la communication.
  • HTTP définit les requêtes et les réponses.
Ces protocoles travaillent ensemble.

3. Anatomie d'une URL

Une URL (Uniform Resource Locator) permet d'identifier une ressource sur le Web. 

https://www.exemple.fr:443/dossier/page.html?id=12#section2
└─┬─┘   └──────┬──────┘└┬─┘└───────┬──────┘ └┬─┘ └───┬───┘
schéma       domaine   port     chemin   paramètre fragment
Élément Valeur Rôle
Schéma https Protocole utilisé.
Domaine www.exemple.fr Nom du serveur.
Port 443 Port de communication.
Chemin /dossier/page.html Emplacement de la ressource.
Paramètre id=12 Information transmise avec la requête.
Fragment section2 Position dans le document.

Le port peut être omis dans l'URL lorsque le navigateur utilise le port par défaut du protocole.

4. Les commandes indispensables

Commande Utilité
ipconfig Afficher la configuration IP.
ipconfig /all Afficher les informations réseau détaillées.
ping 127.0.0.1 Tester la boucle locale.
ping adresse_IP Tester la réponse d'une machine.
ping -6 adresse_IPv6 Tester la réponse d'une machine en IPv6.
nslookup domaine Interroger le DNS.
tracert domaine Observer le chemin réseau.
ipconfig /flushdns Vider le cache DNS local.

Mise en situation professionnelle

Diagnostic
Situation professionnelle Un utilisateur contacte le service informatique :

« Je n'arrive plus à accéder au site de mon entreprise. Pourtant, Internet fonctionne sur les autres ordinateurs. »

En tant que technicien réseau, il faut procéder méthodiquement pour identifier l'origine du problème.

  1. 1
    Vérifier la configuration réseau 
    ipconfig /all

    On vérifie notamment :

    • L'adresse IP.
    • Le masque de sous-réseau.
    • La passerelle par défaut.
    • Le serveur DNS.
  2. 2
    Vérifier la pile réseau locale 
    ping 127.0.0.1

    On vérifie le fonctionnement de la pile réseau locale.

  3. 3
    Vérifier la passerelle 
    ping ADRESSE_PASSERELLE

    On vérifie si la passerelle répond aux requêtes ICMP.

  4. 4
    Vérifier la résolution DNS 
    nslookup www.exemple.fr

    On vérifie si le nom de domaine est correctement résolu.

  5. 5
    Vérifier la connectivité distante 
    ping ADRESSE_IP

    On teste si le serveur distant répond aux requêtes ICMP.

  6. 6
    Observer le chemin réseau 
    tracert www.exemple.fr

    On observe les différents sauts réseau.

  7. 7
    Vérifier le service Web

    On ouvre les outils de développement du navigateur (F12), puis l'onglet Réseau.

    On observe :

    • Les requêtes HTTP.
    • Les codes de statut.
    • Les éventuelles erreurs.
    • Les ressources qui ne se chargent pas.
Conclusion professionnelle Un technicien ne se contente pas de constater qu'un site ne fonctionne pas. Il doit identifier à quel niveau se situe le problème : configuration locale, réseau, DNS, transport, serveur ou application Web.

Bilan — Les outils de diagnostic

Synthèse
Outil Ce qu'il permet de vérifier Ce qu'il ne garantit pas
ping Si une machine répond aux requêtes ICMP. Que le serveur Web fonctionne.
nslookup La résolution d'un nom de domaine. Que le serveur est joignable.
tracert Le chemin observé par les sondes. Que tous les routeurs répondent ou que le chemin applicatif est identique.
Savoir choisir le bon outil
  • Un nom de domaine ne semble pas être résolu : nslookup.
  • On souhaite vérifier si une machine répond : ping.
  • On souhaite observer le chemin réseau : tracert.
  • On souhaite observer les échanges HTTP : outils de développement (F12).
Ces outils sont complémentaires. Aucun ne permet à lui seul de diagnostiquer toutes les pannes.
