Séquence Web — Séance 3 · Mission n°2

Déployer un serveur web local

1ʳᵉ Bac Pro CIEL Durée : 2 h VirtualBox
01

Ce que vous allez apprendre

Objectifs
  • Démarrer une machine virtuelle et vérifier son mode réseau (accès par pont).
  • Installer un serveur web (Apache) avec le gestionnaire de paquets apt.
  • Organiser l'arborescence d'un site : racine /var/www/html, page d'accueil index.html.
  • Gérer un service avec systemctl et vérifier son port d'écoute avec ss.
  • Vérifier l'accès au site via localhost, 127.0.0.1 puis l'adresse IP de la VM.
  • Ouvrir le port 80 dans le pare-feu ufw pour autoriser l'accès depuis un autre poste.
  • Diagnostiquer une panne de serveur web de façon méthodique.
  • Documenter une procédure technique pour un public non spécialiste.

Compétences visées

Bloc 2 · U31 — Installer Mettre en place un service web Installer Apache sur Debian, organiser l'arborescence du site, déposer une page et vérifier le service.
Bloc 2 · U31 — Exploiter un réseau informatique Ouvrir, sécuriser et diagnostiquer Configurer le pare-feu pour autoriser le port d'écoute, valider l'accès distant depuis un autre poste, diagnostiquer une panne niveau par niveau.
Bloc 3 · U32 — Coder Publier une page Déposer un document HTML à la racine du serveur : c'est la première étape vers la publication de vos propres pages.
02

Activité 0 — Créer sa machine virtuelle

Objectif de la phase : chaque commande vous est donnée. Suivez la procédure à la lettre, observez les résultats et répondez aux questions.

  1. 1
    Téléchargement officiel

    Si VirtualBox n'est pas installé sur votre poste, téléchargez et installez-le.

    Aller sur virtualbox.org/wiki/Downloads (site officiel)

  2. 2
    Téléchargement ISO

    Si aucun ISO n'est pas disponible sur votre poste, téléchargez en un.

    Aller sur ubuntu server

  3. 3
    Configuration de la VM

    Créez une nouvelle machine virtuelle dans VirtualBox à partir de l'ISO téléchargé.

    Réalisez une configuration classique : 8 CPU, 8 Go RAM, 10 Go disque dur.

  4. 4
    Démarrer la VM et vérifier le mode réseau
    • Dans VirtualBox, la VM doit être configurée en accès par pont (Configuration → Réseau → mode d'accès réseau : « Accès par pont »).

    Dans la VM, connectez-vous et vérifiez que la VM a bien reçu sa propre adresse IP sur le réseau du lycée :

    ip a

    Relevez dans votre compte rendu :

    Information Valeur relevée
    Adresse IPv4 de la VM (ex. 172.16.12.34)
    Adresse IPv4 du poste Windows hôte (ipconfig dans Windows)
    Adresse IP du serveur de votre voisin
    • Comment reconnaître l'IP de la VM dans ip a ?
      • Repérez l'interface enp0s3 (ou ens33) : l'adresse est indiquée après « inet ».
      • 127.0.0.1 (interface lo) est la boucle locale, ce n'est pas l'adresse réseau de la VM.
      • L'IP de la VM et celle du poste hôte doivent commencer par les mêmes nombres : elles sont sur le même réseau.
    • La VM n'a pas d'adresse IP (pas de ligne inet autre que 127.0.0.1)
      • La VM est probablement en mode NAT : éteignez-la, vérifiez le mode « Accès par pont » dans VirtualBox, redémarrez.
03

Activité 1 — Créer son serveur web

  • 1
    Installer le serveur web Apache

    Dans la VM, saisissez les deux commandes suivantes (sudo = « faire en administrateur » ; tapez le mot de passe quand il est demandé) :

    sudo apt update
    sudo apt install apache2 -y
    • Que font ces commandes ?
      • apt update : met à jour la liste des logiciels disponibles (l'annuaire des paquets), à faire avant toute installation.
      • apt install apache2 : télécharge et installe le serveur web Apache et ses dépendances. -y répond automatiquement « oui ».
      • À la fin, Debian démarre automatiquement le service apache2.
  • 2
    Vérifier le service et son port d'écoute

    Vérifiez que le service Apache est actif :

    systemctl status apache2

    Vous devez voir active (running) en vert. Quittez l'affichage avec Q.

    Vérifiez ensuite sur quel port le serveur écoute :

    ss -tlnp | grep apache
    • Comment lire le résultat ?
      • ss -tlnp liste les ports en écoute : tCP, listening, numériques, processus.
      • Cherchez la ligne contenant 0.0.0.0:80 : Apache écoute sur toutes les interfaces de la VM, port 80.
      • 0.0.0.0 signifie « n'importe quelle adresse de cette machine » : localhost, 127.0.0.1 et l'IP de la VM fonctionneront.
      • Si rien n'apparaît : le service n'est pas démarré, recommencez l'étape 3.
    Question

    1. Sur quel port Apache écoute-t-il ? Quelle commande vous l'a prouvé ?

    2. En quoi systemctl status prouve-t-il qu'Apache est bien un service et pas un simple programme lancé à la main ?

  • 3
    Déposer la page fournie à la racine

    Regardez d'abord ce que contient la racine web livrée avec Apache :

    ls /var/www/html

    Téléchargez la page fournie par l'enseignant directement dans la racine web, puis vérifiez :

    sudo wget https://tansignoret.github.io/1ERE_CIEL/TPs/Srv/index.html -O /var/www/html/index.html
    ls -l /var/www/html
    • Que font ces commandes ?
      • ls liste le contenu d'un dossier. Avant le téléchargement, vous devez voir index.nginx-debian.html ou index.html : la page d'accueil par défaut d'Apache (« Apache2 Default Page »).
      • wget … -O /var/www/html/index.html télécharge le fichier et l'enregistre sous le nom index.html dans la racine web : il remplace la page par défaut.
      • sudo est nécessaire car le dossier /var/www/html n'est modifiable que par l'administrateur.
    • La commande wget échoue (« temporary failure resolving… »)
      • La VM n'a pas accès à internet : vérifiez ip a (étape 1), puis appelez l'enseignant. En dernier recours, recopiez le fichier depuis le poste hôte via un dossier partagé.
  • 4
    Tester les trois adresses locales

    Dans le navigateur du poste Windows (pas besoin de navigateur dans la VM), testez successivement ces trois adresses et notez le résultat de chacune :

    Adresse testée Que désigne-t-elle ? Résultat (page affichée ?)
    http://localhost
    http://127.0.0.1
    l'adresse IP de la VM (relevée à l'étape 1)
    • Attention à un piège
      • localhost et 127.0.0.1 désignent la machine où tourne le navigateur : depuis Windows, ils pointent vers Windows, pas vers la VM !
      • Si la page s'affiche quand même avec ces adresses, c'est que le navigateur est dans la VM (ou qu'un serveur tourne aussi sous Windows…).
    Question

    Ouvrez les outils de développement (F12, onglet Réseau) et rechargez la page : quel code de statut renvoie le serveur ? Quel port apparaît comme port distant ?

  • 5
    Tester depuis la machine d'un autre élève

    Demandez à votre voisin d'ouvrir son navigateur et de saisir l'adresse IP de votre VM (ex. http://172.16.x.x). Faites l'inverse chez lui.

    Test Résultat observé
    Votre page consultée depuis la VM (ou le poste) du voisin
    Question

    1. Le test échoue-t-il ? Votre serveur est-il pour autant « en panne » ?

    2. Quel composant de la VM peut bloquer une connexion entrante alors que le service écoute correctement ?

  • 6
    Ouvrir le port 80 dans le pare-feu

    Le serveur écoute, mais le pare-feu de la VM bloque les connexions entrantes. Dans la VM :

    sudo ufw allow 80/tcp
    sudo ufw enable
    sudo ufw status
    • Que font ces commandes ?
      • ufw allow 80/tcp : crée une règle qui autorise les connexions entrantes TCP vers le port 80.
      • ufw enable : active le pare-feu (si demandé, valide : la connexion SSH, si vous en utilisez une, peut être coupée — dans notre cas, vous travaillez directement dans la VM).
      • ufw status : liste les règles actives. Vous devez voir 80/tcp ALLOW Anywhere.
      • On n'ouvre que le port nécessaire, avec une règle précise : désactiver entièrement le pare-feu est une faute professionnelle.

    Refaite le test de l'étape 6 : votre voisin doit maintenant voir votre page.

    Question

    1. Pourquoi la règle porte-t-elle sur le trafic entrant et pas sortant ?

    2. En séance 1, vous avez consulté des sites HTTPS sur le port 443 : fallait-il ouvrir ce port sur votre poste ? Expliquez la différence de situation.

    • Point de contrôle

    Présentez à l'enseignant : vos relevés (IP de la VM, port d'écoute, sortie de ufw status).

04

Activité 2 — Diagnostiquer une panne

Objectif de la phase : cette fois, ce n'est plus la procédure qu'on vous donne, c'est le symptôme. À vous de trouver la cause, avec une méthode, pas au hasard.

La méthode de diagnostic en 3 niveaux

Quand « ça ne marche pas », on vérifie toujours dans le même ordre, du plus proche au plus lointain :

Niveau Question à se poser Commande de vérification
1. Le service Mon serveur tourne-t-il et écoute-t-il ? systemctl status apache2 puis ss -tlnp | grep apache
2. Le pare-feu Mon pare-feu laisse-t-il entrer le port 80 ? sudo ufw status
3. Le réseau Les deux machines peuvent-elles se joindre ? ip a (même réseau ?) puis ping IP_DU_VOISIN

Cette démarche est exactement celle d'un technicien : on élimine les causes une par une, en prouvant chaque étape, au lieu de tout réinstaller au hasard.

  1. 1
    Provoquer les pannes

    Sur votre VM, provoquez successivement chaque panne, observez le symptôme chez le voisin, utilisez la méthode pour retrouver la cause, puis réparez. Notez à chaque fois le symptôme, la commande qui a révélé le problème et la réparation :

    Panne à provoquer Symptôme observé chez le voisin Diagnostic (niveau + commande) Réparation
    A. Arrêter le service :
    sudo systemctl stop apache2
    B. Fermer le port :
    sudo ufw delete allow 80/tcp

    • Comment redémarrer le service après réparation ?
      • sudo systemctl start apache2 (démarrer) ou sudo systemctl restart apache2 (redémarrer).
    Question 6

    1. Pour les pannes A et B, le ping vers votre VM réussit-il ?

    2. Un camarade vous dit : « mon serveur ne marche pas, je vais le réinstaller ». Quelle question lui posez-vous d'abord, et quelles vérifications lui faites-vous faire avant de toucher à l'installation ?

Point de contrôle

Présentez votre travail à l'enseignant.

Activité 3 — Documenter la procédure

Objectif de la phase : transformer ce que vous avez fait en documentation professionnelle réutilisable. Cette fois, aucune procédure n'est fournie : vous écrivez la vôtre à partir de votre compte rendu.

Mission professionnelle

Vous êtes technicien intervenant pour une association. Vous venez de déployer son serveur web sur une machine dédiée sous Debian. La présidente vous dit :

« La prochaine fois, on voudrait pouvoir refaire cette installation sans faire appel à un prestataire. Écrivez-nous un tuto clair que n'importe quel bénévole peut suivre. »

  1. 1
    Rédiger le tutoriel

    Rédigez un document (traitement de texte) qui explique étape par étape comment installer le serveur web et rendre le site accessible depuis un autre poste. Votre tuto doit comprendre :

    • Un titre et une phrase de contexte (à qui il s'adresse, ce qu'il permet d'obtenir).
    • Les étapes numérotées, dans l'ordre, avec les commandes exactes à taper (installation, vérification du service, page, pare-feu).
    • Au moins 3 captures d'écran des moments clés (service actif, ufw status, page affichée depuis un autre poste).
    • Un encadré « En cas de problème » : la méthode de diagnostic en 3 niveaux, avec les commandes de vérification.
    • Un lexique de 5 mots techniques utilisés, expliqués simplement (service, port, pare-feu, racine web, IP, VM…).
    • À qui j'écris vraiment ?
      • À un bénévole non technicien : pas de jargon non expliqué, une action par étape, des phrases courtes.
      • Testez-vous : « si je n'avais jamais fait ce TP, saurais-je suivre mon tuto sans aide ? »
    • Quelles valeurs sensibles masquer ?
      • Dans les captures, masquez les mots de passe. Les adresses IP du lycée peuvent rester (réseau local de formation).
  2. 2
    Faire relire par un autre binôme

    Échangez votre tuto avec un autre binôme. Chacun lit le tuto de l'autre et répond par écrit à deux questions :

    • « Une étape est-elle ambiguë ou impossible à suivre telle quelle ? Laquelle ? »
    • « Manque-t-il une étape par rapport à ce que nous avons réellement fait en activité 1 ? »

    Corrigez votre tuto à partir de cette relecture (le nom du relecteur figure en fin de document).

Point de contrôle

Présentez à l'enseignant : le tuto finalisé (avec captures, encadré « En cas de problème » et lexique).

07

Vocabulaire et concepts essentiels

Connaissances
Notion L'essentiel
Machine virtuelle (VM) Ordinateur « logiciel » qui tourne dans votre poste Windows grâce à VirtualBox. Sa configuration réseau détermine qui peut la joindre.
Mode « accès par pont » Mode réseau dans lequel la VM obtient sa propre adresse IP sur le réseau du lycée (DHCP), comme un vrai poste. C'est ce qui permettra à votre voisin de voir votre serveur.
Snapshot « Photo » de l'état de la VM. Le snapshot TP3 - départ vous ramène en 10 secondes à une machine propre en cas de problème.
Serveur web Programme service qui écoute en permanence sur un port (généralement 80) et répond aux requêtes HTTP en renvoyant des fichiers. Apache est le serveur web le plus répandu.
Service Programme qui tourne en arrière-plan, sans fenêtre, démarré et supervisé par le système. Sous Debian, on le gère avec systemctl.
Port d'écoute « Porte » logique sur laquelle le service attend les clients. HTTP = port 80, HTTPS = port 443 (vu en séance 1).
Racine web (/var/www/html) Dossier qu'Apache est autorisé à servir. Un fichier qui n'est pas dedans n'est pas accessible depuis le navigateur.
index.html Page affichée par défaut quand on demande la racine du site (sans nom de fichier).
localhost / 127.0.0.1 La boucle locale : « moi-même ». Tester avec permet de vérifier le serveur sans passer par le réseau (vu au TP « Le voyage d'une requête web »).
Pare-feu ufw Gardien de la VM : il filtre le trafic entrant. Par défaut, tout est bloqué : votre serveur sera joignable localement mais pas par les autres postes… tant que vous n'avez pas ouvert le port.

Mot Définition
Machine virtuelle (VM) Ordinateur simulé par logiciel, qui possède son propre système (ici Debian) et sa propre adresse IP.
Accès par pont Mode réseau de la VM : elle obtient sa propre IP sur le réseau du lycée, comme un vrai poste.
Snapshot État sauvegardé d'une VM, qu'on peut restaurer en quelques secondes.
Service Programme qui tourne en arrière-plan sans fenêtre, démarré et supervisé par le système (systemctl sous Debian).
Port d'écoute Numéro logique sur lequel un service attend les clients. HTTP : 80, HTTPS : 443.
APT Gestionnaire de paquets de Debian : installe les logiciels et leurs dépendances (apt install).
Racine web (/var/www/html) Dossier unique qu'Apache est autorisé à servir ; son contenu est accessible, le reste ne l'est pas.
index.html Page servie par défaut quand on demande un dossier sans nom de fichier.
localhost / 127.0.0.1 La boucle locale : désigne toujours la machine elle-même, sans passer par le réseau.
Pare-feu (ufw) Programme qui filtre le trafic réseau entrant (et sortant) selon des règles.
Règle de trafic entrant Autorisation donnée au pare-feu d'accepter les connexions vers un port précis (ex. TCP 80).
DHCP Service qui attribue automatiquement les adresses IP ; l'adresse d'une machine peut donc changer d'une session à l'autre.
