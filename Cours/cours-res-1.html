Cours — Séquence Web · Séance 1

Le voyage d'une requête : internet, client-serveur et HTTP

Vous tapez une adresse, la page s'affiche. Derrière ce geste simple se cache un dialogue précis entre un client et un serveur, guidé par le DNS. Ce cours vous donne toutes les clés pour comprendre — et prouver — l'acheminement d'une page web.

Première Bac Pro CIEL Durée : 30 min Outils : navigateur, cmd, outils de développement
01

Internet, c'est quoi au juste ?

Structure

Internet (« inter-networks » : « entre les réseaux ») est l'interconnexion de millions de réseaux à travers le monde. Ce n'est pas un service, mais une infrastructure.

  • Réseau local (LAN) : le réseau de la salle, de l'atelier ou de la maison.
  • FAI (Fournisseur d'Accès à Internet) : il relie votre réseau local au reste du monde via ses routeurs.
  • Le web : un service qui circule sur internet — parmi d'autres (messagerie, streaming, jeux…).
À retenir

Le web est un service qui utilise internet, comme la voix utilise le réseau téléphonique. Confondre « web » et « internet » est l'erreur la plus répandue… et la plus corrigée en interrogation.

02

Le modèle client-serveur

Fondamentaux

Presque tout ce que vous faites sur le web repose sur un seul principe :

  • Le client (votre navigateur) formule une requête et attend.
  • Le serveur (une machine allumée 24 h/24) écoute sur un port et répond.
  • Le dialogue respecte un protocole commun : HTTP.
sequenceDiagram participant C as Client (navigateur) participant D as Serveur DNS participant S as Serveur web C->>D: Quelle est l'IP de tansignoret.github.io ? D-->>C: 185.199.108.153 C->>S: GET /1ERE_CIEL/TPs/tp_web_bases.html S-->>C: 200 OK + document HTML Note over C,S: Puis le navigateur demande les autres ressources (CSS, images…)

Le dialogue complet : une interrogation DNS, puis un échange HTTP entre client et serveur.

Ports à connaître par cœur

HTTP : port 80 · HTTPS : port 443 (le « s » de secure = échanges chiffrés). À comparer : SSH 22, DNS 53, SMTP 25, POP3 110.

03

Décoder une URL

Adresse

L'URL (Uniform Resource Locator) est l'adresse complète d'une ressource du web :

https://tansignoret.github.io/1ERE_CIEL/TPs/tp_web_bases.html
└─┬─┘   └──────────┬──────────┘└────┬────┘└─────────┬──────────┘
schéma           domaine          dossier        fichier
  • Schéma : le protocole utilisé (https). Il est choisi par le propriétaire du site.
  • Nom de domaine : le nom lisible du serveur. Choisit et enregistré par le propriétaire du site.
  • Chemin et fichier : l'organisation interne des dossiers du serveur.
Piège classique

Le navigateur ne comprend que les adresses IP : avant tout échange, le nom de domaine doit être traduit en IP. C'est le travail du DNS.

04

Le DNS : l'annuaire du web

Résolution

Le DNS (Domain Name System) est un annuaire mondial et distribué : aucun serveur ne connaît tous les noms, mais chacun sait vers qui rediriger la question.

flowchart LR A[Poste client] --> B[Résolveur DNS du FAI] B --> C[Racine .] B --> D[TLD .io] B --> E[Serveur autoritaire tansignoret.github.io] E --> F[IP : 185.199.108.153] F --> B --> A

La résolution descend l'arbre : racine → domaine de premier niveau → serveur autoritaire.

  • Le résultat est mis en cache : une requête suivante sera plus rapide.
  • Commandes utiles : nslookup (interroger le DNS), ping (tester la joignabilité d'une machine).
05

HTTP : requête, réponse, codes de statut

Protocole

HTTP (HyperText Transfer Protocol) est le protocole du dialogue web. Un échange comporte toujours deux parties, chacune portant des en-têtes (headers) :

Envoyés par le client Envoyés par le serveur
Exemples d'en-têtes Host (site demandé), User-Agent (navigateur) Server (logiciel serveur), Content-Type (type de document)
Contenu La requête : GET /page.html La réponse : code de statut + document (HTML, image…)

Les codes de statut à connaître

Code Signification
200 Succès : le serveur renvoie le document demandé.
301 Déplacé de façon permanente : la ressource a changé d'adresse.
403 Interdit : la ressource existe mais l'accès est refusé.
404 Introuvable : la ressource demandée n'existe pas sur le serveur.
5xx Erreur du serveur (ex. 500 : le serveur a échoué).
Où les observer ?

Dans le navigateur : F12 → onglet Réseau → recharger la page (F5). Chaque ligne est un échange HTTP : requête, statut, en-têtes, contenu.

HTTPS : le « s » de sécurisé

HTTPS = HTTP + chiffrement (protocole TLS). Un tiers qui intercepte les échanges ne peut plus les lire. Le chiffrement protège les échanges ; il ne rend pas pour autant un site inviolable.

06

Prouver le trajet : les outils du technicien

Méthode
Outil Ce qu'il prouve Ce qu'il ne prouve PAS
ping La machine est joignable (réseau OK, machine allumée). Que le service web fonctionne (ping = ICMP, pas HTTP).
nslookup Le DNS traduit correctement le nom en adresse IP. Que le serveur répond (un nom peut exister sans service actif).
tracert La route : les routeurs traversés, dans l'ordre. L'état des services du serveur de destination.
Outils de développement (F12) Le dialogue HTTP réel : méthodes, statuts, en-têtes, contenu. Ce qui se passe sur les machines intermédiaires.
Démarche du technicien

Comme pour le test réseau (localhost → passerelle → Internet), on ne teste jamais au hasard : chaque outil répond à une question précise, et chaque réponse obtenue oriente la question suivante.

07

L'essentiel en un schéma

Synthèse
flowchart LR A[Utilisateur
tape une URL] --> B[Navigateur
le client] B --> C[Serveur DNS
nom → IP] B --> D[Routeurs
passerelle + FAI] D --> E[Serveur web
écoute sur le port 443] E --> D --> B --> A

Une interrogation DNS, un aller-retour HTTP : c'est tout le « voyage d'une requête ».

  • Le web est un service qui circule sur internet.
  • Le navigateur est le client ; le site est hébergé sur un serveur qui écoute sur un port (80/443).
  • Le DNS traduit le nom en IP une seule fois, au début ; il ne participe pas au dialogue HTTP.
  • HTTP : requête → réponse avec code de statut (200, 301, 403, 404…).
  • Un ping qui répond prouve que la machine est joignable, pas que le service web fonctionne.
