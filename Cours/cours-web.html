01

Internet et le web : ne pas confondre

Structure

Internet (« inter-networks » : « entre les réseaux ») est l'interconnexion de millions de réseaux à travers le monde. Ce n'est pas un service : c'est une infrastructure, composée de machines et de liaisons.

  • Réseau local (LAN) : le réseau de la salle, de l'atelier ou de la maison.
  • FAI (Fournisseur d'Accès à Internet) : il relie votre réseau local au reste du monde via ses routeurs.
  • Le web : un service qui circule sur internet — parmi d'autres (messagerie, streaming, jeux en ligne…).
02

Le modèle client-serveur

Fondamentaux

Presque tout ce que vous faites sur le web repose sur un seul principe :

  • Le client (votre navigateur) formule une requête et attend.
  • Le serveur web — un service qui tourne en permanence sur une machine — écoute sur un port et répond.
  • Le dialogue respecte un protocole commun : HTTP.

Élément Ce qu'il fait Où vous l'avez vu
Client Programme qui émet une requête et attend une réponse (ex. navigateur). Séance 1 : F12, onglet Réseau.
Serveur web Service qui écoute sur un port et sert les fichiers de sa racine (/var/www/html). Séances 3-4 : Apache sur votre VM.
Service Programme en arrière-plan, démarré et supervisé par le système (systemctl). Séance 3 : systemctl status apache2.
Port d'écoute « Porte » logique sur laquelle le service attend les clients. Séance 3 : ss -tlnp, ufw allow 80/tcp.
Ports à connaître par cœur

HTTP : port 80 · HTTPS : port 443 (le « s » de secure = échanges chiffrés). À comparer : SSH 22, DNS 53, SMTP 25, POP3 110, IMAP 143, RDP 3389.

03

Les grandes technologies du web

Technologies

Une page web n'est pas une image envoyée d'un coup : c'est du texte et des fichiers que le navigateur transforme en page. Quatre technologies jouent des rôles différents :

Technologie Rôle La question à laquelle elle répond
HTML Structure et contenu de la page (balises). « Qu'est-ce qu'il y a ? »
CSS Présentation, mise en forme. « À quoi ça ressemble ? »
JavaScript Interactivité, comportements dynamiques. « Que se passe-t-il au clic ? »
HTTP / HTTPS Protocole d'échange entre client et serveur. « Comment ça se transmet ? »
La métaphore de la maison

Le HTML est les murs et les pièces, le CSS est la peinture et la décoration, le JavaScript est l'électricité et les interrupteurs. Pas de page web sans HTML — comme pas de maison sans murs. Et HTTP est le camion qui livre les plans.

04

URL et DNS : trouver le serveur

Adressage

L'URL (Uniform Resource Locator) est l'adresse complète d'une ressource du web :

https://tansignoret.github.io/1ERE_CIEL/TPs/tp_web_bases.html
└─┬─┘   └──────────┬──────────┘└────┬────┘└─────────┬──────────┘
schéma           domaine          dossier        fichier
  • Schéma : le protocole utilisé (https).
  • Nom de domaine : le nom lisible du serveur, enregistré par le propriétaire du site.
  • Chemin et fichier : l'organisation interne des dossiers du serveur — vous avez créé la vôtre en séance 4 (/var/www/html/index.html).
Piège classique

Le navigateur ne comprend que les adresses IP : avant tout échange, le nom de domaine doit être traduit en IP. C'est le travail du DNS.

Le DNS (Domain Name System) est l'annuaire mondial du web : il traduit www.education.gouv.fr en adresse IP. Il est distribué (aucun serveur ne connaît tous les noms), il met en cache ses réponses, et il peut renvoyer plusieurs adresses pour un même site (hébergement multiple, répartition de charge, CDN).

Le DNS intervient une seule fois, au début : il ne participe pas au dialogue HTTP qui suit.

05

Le dialogue HTTP : requête, réponse, statut

Protocole

HTTP (HyperText Transfer Protocol) est le protocole du dialogue web. Un échange comporte toujours deux parties, chacune portant des en-têtes (headers) :

Envoyés par le client Envoyés par le serveur
Exemples d'en-têtes Host (site demandé), User-Agent (navigateur) Server (logiciel serveur), Content-Type (type de document)
Contenu La requête : GET /page.html La réponse : code de statut + document (HTML, image…)

Les codes de statut à connaître

Famille Sens Codes à connaître
2xx Succès 200 OK : le serveur renvoie le document demandé.
3xx Redirection 301 : la ressource a changé d'adresse définitivement.
4xx Erreur côté client 403 interdit · 404 introuvable (vous l'avez provoquée en séance 1).
5xx Erreur côté serveur 500 : le serveur a échoué, 503 : indisponible.
404 : piège classique

Un 404 ne signifie pas que le serveur est en panne : il a été joint, il a traité la requête, mais la ressource n'existe pas. La panne et l'erreur client sont deux situations différentes.

HTTPS : le « s » de sécurisé

HTTPS = HTTP + chiffrement (protocole TLS). Trois garanties : la confidentialité (un intercepteur ne lit rien), l'intégrité (les données ne sont pas modifiées en route) et l'authentification du serveur (certificat). Attention : HTTPS protège les échanges, il ne garantit pas que le site est honnête.

06

Qui fait quoi ? Les acteurs du voyage

Récapitulatif
Acteur Rôle dans le voyage d'une requête Ordre
Utilisateur Saisit l'URL dans le navigateur. 1
Navigateur (client) Découpe l'URL, obtient l'IP via le DNS, envoie la requête HTTP, reçoit et assemble la page (DOM, CSS, images, JS). 2, 7, 9
Serveur DNS Traduit le nom de domaine en adresse IP. 3
Passerelle puis routeurs du FAI Acheminent les paquets de réseau en réseau jusqu'au serveur. 4-6
Serveur web Reçoit la requête sur son port d'écoute, renvoie une réponse avec un code de statut. 8
À retenir

Le premier équipement traversé est toujours la passerelle : c'est la seule porte du réseau local. Le navigateur n'envoie rien au serveur avant d'avoir obtenu son IP du DNS.

07

Prouver et diagnostiquer : les outils du technicien

Méthode
Outil Ce qu'il prouve Ce qu'il ne prouve PAS
ping La machine est joignable (elle répond à l'ICMP) et le temps de réponse. Que le service web fonctionne (ping ≠ HTTP).
nslookup Le DNS traduit le nom en adresse IP. Que le serveur est joignable ou que le service répond.
tracert La route suivie : les routeurs traversés, dans l'ordre. Que tous les routeurs répondent (les * ne sont pas des pannes) ni l'état du service distant.
systemctl status Le service est actif (« running ») ou arrêté. Que le port est ouvert dans le pare-feu.
ss -tlnp Le port d'écoute du service (0.0.0.0:80 LISTENING). Que les clients distants peuvent y accéder.
ufw status Les ports ouverts dans le pare-feu. Que le service derrière le port fonctionne.
Outils de développement (F12) Le dialogue HTTP réel : méthodes, statuts, en-têtes, contenu. Ce qui se passe sur les machines intermédiaires.
La méthode de diagnostic en 3 niveaux

Quand « ça ne marche pas », on vérifie toujours dans le même ordre : 1. le service (systemctl status, ss -tlnp) → 2. le pare-feu (ufw status) → 3. le réseau (ip a, ping). On élimine les causes une par une, en prouvant chaque étape — jamais au hasard.

Une interrogation DNS, un aller-retour HTTP : c'est tout le « voyage d'une requête ».

  • Le web est un service qui circule sur internet.
  • Le navigateur est le client ; le site est hébergé sur un serveur web, service qui écoute sur un port (80/443) et sert sa racine.
  • Une page est un assemblage de ressources : HTML (structure), CSS (forme), JS (interactivité), transportées par HTTP/HTTPS.
  • Le DNS traduit le nom en IP une seule fois, au début.
  • Chaque réponse HTTP porte un code de statut (200, 301, 403, 404, 5xx).
  • Le diagnostic se fait niveau par niveau : service → pare-feu → réseau, avec l'outil adapté à chaque question.
