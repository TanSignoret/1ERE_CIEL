01

Introduction à Git

Pourquoi Git ?

Git est un système de contrôle de version (VCS) qui permet de :

  • Sauvegarder l'historique des modifications de votre code.
  • Travailler en équipe sans écraser le travail des autres.
  • Revenir en arrière si une modification introduit un bug.
  • Créer des branches pour développer de nouvelles fonctionnalités en parallèle.

Utilisé par des millions de développeurs dans le monde, Git est devenu un standard en entreprise pour la gestion de projets informatiques, y compris en administration réseau et cybersécurité.

02

L'histoire de Git : Linus Torvalds et Linux

Contexte historique

Git a été créé en 2005 par Linus Torvalds, le créateur du noyau Linux. Voici comment tout a commencé :

1991 : Naissance de Linux

Linus Torvalds crée le noyau Linux, un système d'exploitation open-source. Linux devient rapidement populaire grâce à sa stabilité et sa flexibilité.

2002-2005 : L'ère BitKeeper

Pour gérer le développement de Linux, l'équipe utilise BitKeeper, un outil propriétaire de contrôle de version. En 2005, BitKeeper retire sa licence gratuite pour Linux, ce qui pose un problème majeur.

Avril 2005 : Naissance de Git

Linus Torvalds décide de créer son propre outil : Git. En seulement 2 semaines, Git est fonctionnel et répond aux besoins suivants :

  • Rapidité : Git est optimisé pour être extrêmement rapide.
  • Décentralisation : Chaque développeur a une copie complète du dépôt.
  • Intégrité des données : Chaque commit est identifié par un hash SHA-1.
  • Branches légères : Créer et fusionner des branches est simple et efficace.

2008 : GitHub voit le jour

GitHub est lancé en 2008, offrant une interface web pour héberger des dépôts Git. GitHub ajoute des fonctionnalités comme les Pull Requests, les Issues, et les Actions (CI/CD). Aujourd'hui, GitHub est la plateforme la plus utilisée pour le développement collaboratif.

03

Pourquoi Git est-il indispensable en entreprise ?

Avantages

Git est devenu un standard dans l'industrie pour plusieurs raisons :

1. Collaboration simplifiée

Git permet à plusieurs développeurs de travailler sur le même projet simultanément :

  • Chaque développeur travaille sur sa propre branche.
  • Les modifications sont fusionnées dans la branche principale une fois validées.
  • Les conflits sont gérés de manière structurée.
* commit 3 (main) |\ | * commit 2 (feature/login) |/ * commit 1

Exemple de fusion de branche : la branche feature/login est fusionnée dans main.

2. Historique complet et traçable

Chaque modification est enregistrée avec :

  • Un message de commit décrivant le changement.
  • Un hash unique (SHA-1) pour identifier le commit.
  • La date et l'auteur du commit.

Cela permet de :

  • Savoir qui a fait quoi et quand.
  • Revenir en arrière si une modification introduit un bug.
  • Comprendre l'évolution du projet.

3. Branches et isolation des fonctionnalités

Les branches permettent de :

  • Travailler sur une nouvelle fonctionnalité sans affecter le code principal.
  • Tester des idées expérimentales sans risque.
  • Isoler les corrections de bugs dans des branches dédiées.
gitGraph commit branch feature/login commit commit checkout main commit merge feature/login

Exemple de workflow avec branches : développement d'une fonctionnalité en parallèle.

4. Sécurité et intégrité des données

Git utilise des hashs cryptographiques (SHA-1) pour garantir :

  • L'intégrité des données : toute modification d'un commit invalide son hash.
  • La traçabilité : chaque commit est lié à son parent.
  • La résistance aux corruptions : Git détecte les altérations des données.

5. Décentralisation

Contrairement aux systèmes centralisés (comme SVN), Git est décentralisé :

  • Chaque développeur a une copie complète du dépôt (historique + fichiers).
  • Pas de point de défaillance unique : si un serveur tombe, les copies locales restent disponibles.
  • Possibilité de travailler hors ligne et de synchroniser plus tard.
04

Les concepts clés de Git

Terminologie

Voici les concepts fondamentaux à maîtriser pour utiliser Git efficacement :

Dépôt (Repository)

Un dépôt Git est un dossier où Git stocke :

  • L'historique complet du projet (commits).
  • Les fichiers du projet.
  • Les branches et tags.

Commande : git init (initialise un dépôt local).

Commit

Un commit est une sauvegarde d'un état du code à un instant donné. Chaque commit contient :

  • Un hash unique (ex: a1b2c3d4...).
  • Un message décrivant les changements.
  • Un auteur et une date.
  • Un parent (le commit précédent).

Commande : git commit -m "Message".

Branche (Branch)

Une branche est une version parallèle du code. Elle permet de :

  • Travailler sur une nouvelle fonctionnalité sans affecter la branche principale.
  • Expérimenter sans risque.
  • Corriger des bugs dans un environnement isolé.

Commandes :

  • git branch : Lister les branches.
  • git branch nom-branche : Créer une nouvelle branche.
  • git checkout nom-branche : Basculer vers une branche.

Merge (Fusion)

La fusion (merge) permet d'intégrer les modifications d'une branche dans une autre.

  • Fast-forward : Si la branche n'a pas divergé, Git avance simplement le pointeur.
  • Merge commit : Si les branches ont divergé, Git crée un commit de fusion.

Commande : git merge nom-branche.

Clone et Remote

  • Clone : Copier un dépôt distant en local.

    Commande : git clone https://github.com/utilisateur/repo.git.

  • Remote : Référence à un dépôt distant (ex: GitHub).

    Commandes :

    • git remote add origin https://github.com/utilisateur/repo.git
    • git push origin main : Envoyer les modifications.
    • git pull origin main : Récupérer les modifications.

Conflit (Conflict)

Un conflit survient lorsque deux modifications incompatibles sont faites sur la même partie du code. Git marque les conflits dans le fichier : 

<<<<< HEAD
print("Version de la branche actuelle")
=======
print("Version de la branche fusionnée")
>>>>> nom-branche

Résolution :

  1. Ouvrir le fichier en conflit.
  2. Choisir quelle version garder (ou fusionner manuellement).
  3. Faire un git add sur le fichier résolu.
  4. Valider avec git commit.

Les commandes Git essentielles

Référence

Voici les commandes Git les plus utilisées, classées par catégorie :

📌 Configuration initiale

Configurer Git avec votre nom et email (nécessaire pour les commits) : 

git config --global user.name "Votre Nom"
git config --global user.email "votre@email.com"

📁 Manipulation d'un dépôt

Action Commande Description
Initialiser un dépôt git init Crée un nouveau dépôt Git dans le dossier courant.
Cloner un dépôt git clone https://github.com/utilisateur/repo.git Copie un dépôt distant en local.
Voir l'état git status Affiche les fichiers modifiés, ajoutés ou non suivis.

📝 Ajouter et valider des modifications

Action Commande Description
Ajouter un fichier git add fichier.py Ajoute un fichier spécifique à l'index.
Ajouter tous les fichiers git add . Ajoute tous les fichiers modifiés/nouveaux.
Faire un commit git commit -m "Message" Valide les modifications avec un message.
Modifier le dernier commit git commit --amend Modifie le message ou ajoute des fichiers au dernier commit.

🌿 Gérer les branches

Action Commande Description
Lister les branches git branch Affiche la liste des branches locales.
Créer une branche git branch nom-branche Crée une nouvelle branche.
Basculer vers une branche git checkout nom-branche Change de branche.
Créer et basculer git checkout -b nom-branche Crée une nouvelle branche et bascule dessus.
Fusionner une branche git merge nom-branche Fusionne nom-branche dans la branche actuelle.
Supprimer une branche git branch -d nom-branche Supprime une branche locale (si elle a été fusionnée).

🔄 Synchronisation avec un dépôt distant

Action Commande Description
Envoyer les modifications git push origin main Envoie les commits locaux vers le dépôt distant.
Récupérer les modifications git pull origin main Récupère les commits distants et fusionne avec la branche locale.
Récupérer sans fusionner git fetch origin Récupère les commits distants sans fusionner.
Lister les dépôts distants git remote -v Affiche les URL des dépôts distants (ex: origin).

🔍 Inspection et historique

Action Commande Description
Voir l'historique git log Affiche l'historique des commits.
Voir l'historique (version compacte) git log --oneline Affiche les commits sur une seule ligne.
Voir les différences git diff Affiche les modifications non commitées.
Voir les différences d'un commit git show hash-commit Affiche les modifications d'un commit spécifique.
Voir l'historique graphique git log --graph --oneline --all Affiche l'historique avec un graphique des branches.

Visualiser Git avec des graphiques

Illustrations

Les graphiques permettent de visualiser l'historique et les branches d'un dépôt Git. Voici quelques exemples :

🌳 Historique linéaire

Un dépôt avec des commits successifs sur une seule branche (main) :

* commit 3 (main) * commit 2 * commit 1

Commande pour afficher ce graphique : 

git log --graph --oneline

🌿 Branches et merges

Un dépôt avec une branche feature/login fusionnée dans main :

gitGraph commit id: "1" branch feature/login commit id: "2" commit id: "3" checkout main commit id: "4" merge feature/login

Explications :

  • commit 1 : Commit initial sur main.
  • commit 2 et commit 3 : Commits sur la branche feature/login.
  • commit 4 : Commit sur main en parallèle.
  • merge : Fusion de feature/login dans main.

🔀 Conflit de merge

Lorsque deux branches modifient la même ligne, Git ne peut pas fusionner automatiquement :

* commit 5 (main) |\ | * commit 4 (feature/login) ← Modifie la ligne 10 * | commit 3 (main) ← Modifie la ligne 10 |/ * commit 2

Résolution :

  1. Git marque le conflit dans le fichier : 
    <<<<< HEAD
print("Version de main")
=======
print("Version de feature/login")
>>>>> feature/login
  2. L'utilisateur doit choisir quelle version garder (ou fusionner manuellement).
  3. Faire un git add sur le fichier résolu.
  4. Valider avec git commit.

07

Workflow Git en entreprise

Bonnes pratiques

Voici un workflow typique pour utiliser Git en équipe :

gitGraph commit id: "1" tag: "v1.0" branch develop commit id: "2" commit id: "3" checkout main branch feature/login commit id: "4" commit id: "5" checkout develop merge feature/login commit id: "6" tag: "v2.0" branch release/v2.0 commit id: "7" checkout main merge release/v2.0 commit id: "8" tag: "v2.0"

📋 Étapes détaillées

  1. Cloner le dépôt : 
    git clone https://github.com/entreprise/projet.git

    Crée une copie locale du dépôt.

  2. Créer une branche de fonctionnalité : 
    git checkout -b feature/ma-fonctionnalite

    Crée une nouvelle branche pour développer une fonctionnalité.

  3. Travailler sur la branche :
    • Faire des commits réguliers : 
      git add .
git commit -m "Ajout de la fonction X"
    • Pousser la branche vers le dépôt distant : 
      git push origin feature/ma-fonctionnalite
  4. Créer une Pull Request (PR) :

    Sur GitHub/GitLab, créer une PR pour fusionner feature/ma-fonctionnalite dans develop ou main.

    • Un collègue revise le code (code review).
    • La PR est validée si tout est correct.
    • La PR est fusionnée dans la branche cible.

  5. Mettre à jour sa branche locale : 
    git pull origin main

    Récupère les dernières modifications de la branche principale.

💡 Bonnes pratiques

  • Commits atomiques :

    Un commit = un changement logique (ex: "Corrige bug login" et non "Modifications diverses").

  • Messages de commit clairs :

    Éviter les messages vagues comme "fix" ou "update". Préférer :

    • ✅ "Ajout validation mot de passe"
    • ✅ "Corrige bug division par zéro"
    • ❌ "fix"

  • Branches courtes :

    Fusionner souvent pour éviter les conflits et garder un historique propre.

  • Pull avant push :

    Toujours faire un git pull avant de pousser pour éviter les conflits.

  • .gitignore :

    Exclure les fichiers inutiles (ex: __pycache__/, *.log) avec un fichier .gitignore.

Outils et intégrations pour Git

Écosystème

Git est souvent utilisé avec des plateformes d'hébergement et des outils graphiques pour faciliter son utilisation.

🌍 Plateformes d'hébergement

Outil Description Lien Avantages
GitHub Plateforme la plus populaire pour héberger des dépôts Git. github.com
  • Communauté très active.
  • Intégrations nombreuses (CI/CD, bots, etc.).
  • Gratuit pour les dépôts publics.
GitLab Alternative à GitHub avec DevOps intégré. gitlab.com
  • Auto-hébergement possible.
  • Intégration native avec CI/CD.
  • Gratuit pour les dépôts privés (limite de stockage).
Bitbucket Solution d'Atlassian, souvent utilisée en entreprise. bitbucket.org
  • Intégration avec Jira et Trello.
  • Gratuit pour les petites équipes.

🖥️ Outils graphiques

Outil Description Lien Avantages
GitKraken Client Git graphique avec interface intuitive. gitkraken.com
  • Visualisation claire des branches.
  • Gratuit pour l'éducation.
  • Prise en charge de GitHub, GitLab, Bitbucket.
Sourcetree Client Git gratuit par Atlassian. sourcetreeapp.com
  • Simple et intuitif.
  • Intégration avec Bitbucket.
VS Code + GitLens Extension pour VS Code qui améliore l'intégration Git. GitLens
  • Visualisation des modifications directement dans le code.
  • Historique des commits par ligne.
  • Gratuit et open-source.

🔧 Intégration avec les IDE

La plupart des IDE modernes intègrent Git nativement :

  • VS Code : Support natif de Git + extensions comme GitLens.
  • PyCharm : Intégration Git avancée (visualisation des branches, résolution des conflits).
  • IntelliJ IDEA : Idéal pour le développement Java/Kotlin avec Git.
  • Eclipse : Plugin EGit pour Git.
